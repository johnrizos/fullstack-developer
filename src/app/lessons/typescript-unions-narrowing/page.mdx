# Unions, Narrowing & Type Guards

Τα union types είναι το καθημερινό εργαλείο του TypeScript και το θεμέλιο των πιο δυνατών patterns. Αυτό το μάθημα καλύπτει: literal unions (και γιατί αντικαθιστούν τα `enum`), το `as const`, narrowing, **discriminated unions** με exhaustiveness/`never`, και **custom type guards** — όλα όσα χρειάζεσαι για να μοντελοποιείς καταστάσεις ώστε ο compiler να κάνει τα invalid states αδύνατα να γραφτούν.

## Union types & narrowing

Ένα union λέει «μία από αυτές τις δυνατότητες»:

```ts
type TaskStatus = "todo" | "doing" | "done";
```

Με unions έρχεται το **narrowing** — ο compiler «στενεύει» τον τύπο καθώς ελέγχεις, χωρίς casts:

```ts
function describe(value: string | number | null) {
  if (value === null) return "empty";        // εδώ: null
  if (typeof value === "string") {
    return value.toUpperCase();              // εδώ: string
  }
  return value.toFixed(2);                   // εδώ: number
}
```

## Η εργαλειοθήκη του narrowing

Ο compiler «καταλαβαίνει» συγκεκριμένα μοτίβα JavaScript. Αυτά είναι όλα:

```ts
typeof value === "string"        // primitives: string, number, boolean, symbol, bigint,
                                 // undefined, object, function
value instanceof Error           // classes (υπάρχουν στη runtime)
Array.isArray(value)             // πίνακες — το typeof [] είναι "object"!
"meow" in animal                 // ύπαρξη property
value === "done"                 // ισότητα με literal (discriminated unions)
value !== null                   // αποκλεισμός null/undefined
if (value) { }                   // truthiness
isCat(value)                     // custom type guard (παρακάτω)
```

Δύο παγίδες που κοστίζουν χρόνο:

```ts
function f(x: string | null) {
  if (typeof x === "object") {
    // εδώ ο τύπος είναι null — typeof null === "object" (ιστορικό bug της JS)
  }
}

function g(count: number | undefined) {
  if (count) {
    // ❌ το 0 είναι falsy — μπαίνεις εδώ μόνο για count !== 0
  }
  if (count !== undefined) {
    // ✅ ο σωστός έλεγχος
  }
}
```

Το **truthiness narrowing** είναι βολικό αλλά κόβει και το `0`, το `""`, το `NaN`. Για αριθμούς και strings, έλεγξε ρητά `!== undefined` / `!== null` (ή `!= null`, που πιάνει και τα δύο).

### Χάνοντας το narrowing

Το narrowing ισχύει μέσα σε ένα «κλειστό» κομμάτι κώδικα. Χάνεται όταν ο compiler δεν μπορεί να εγγυηθεί ότι η τιμή δεν άλλαξε:

```ts
let value: string | null = getValue();

if (value !== null) {
  doSomething(() => {
    value.toUpperCase();  // ❌ σε callback: ο compiler δεν ξέρει πότε θα τρέξει
  });
}

// Λύση: αντέγραψε σε const
const v = value;
if (v !== null) {
  doSomething(() => v.toUpperCase()); // ✅ ένα const δεν αλλάζει
}
```

Ίδιο πρόβλημα και με properties αντικειμένων (`obj.value` μπορεί να άλλαξε μεταξύ των γραμμών). Ο κανόνας: **narrow-άρεις μια `const` τοπική μεταβλητή**, όχι ένα mutable πεδίο.

## `?.` και `??` — τα δύο τελεστές που θα γράφεις κάθε μέρα

Δεν είναι TypeScript features (είναι JavaScript), αλλά ο compiler τα καταλαβαίνει ως narrowing και χωρίς αυτά δεν γράφεις καθαρό strict κώδικα:

```ts
const city = user.address?.city;         // αν το address είναι null/undefined → undefined
const name = user.getName?.();           // κλήση μόνο αν υπάρχει η μέθοδος
const first = list?.[0];                 // ασφαλής index access

const port = config.port ?? 3000;        // αν είναι null/undefined → 3000
const port2 = config.port || 3000;       // ❌ και το 0 γίνεται 3000!
```

Η διαφορά `??` vs `||` είναι κλασική ερώτηση: το `||` πέφτει πίσω σε **κάθε falsy** τιμή (`0`, `""`, `false`), το `??` **μόνο** σε `null`/`undefined`. Για defaults σε αριθμούς και booleans, το `??` είναι σχεδόν πάντα το σωστό.

## Assertion functions — `asserts x is T`

Μια παραλλαγή του type guard: αντί να επιστρέφει `boolean`, **πετάει** αν κάτι δεν ισχύει — και ο compiler θεωρεί τον τύπο στενεμένο για **όλη την υπόλοιπη** function:

```ts
function assertIsDefined<T>(value: T): asserts value is NonNullable<T> {
  if (value === null || value === undefined) {
    throw new Error("Expected value to be defined");
  }
}

function process(user: User | null) {
  assertIsDefined(user);
  user.name;   // ✅ από εδώ και κάτω: User — χωρίς if, χωρίς !
}
```

Χρήσιμο σε invariants που «ξέρεις» ότι ισχύουν (μετά από validation, σε tests, σε setup κώδικα). Προσοχή σε δύο πράγματα: η function **πρέπει** να έχει explicit return type annotation (αλλιώς δεν δουλεύει), και σε αντίθεση με το `!`, εδώ υπάρχει **πραγματικός runtime έλεγχος**.

## enum vs `as const` vs literal unions

Το TypeScript έχει `enum` — το μοναδικό feature του που **παράγει runtime κώδικα** αντί να εξαφανίζεται. Στα modern codebases συχνά αποφεύγεται:

```ts
enum Status { Todo, Doing, Done }        // numeric enum: Todo = 0, Doing = 1, Done = 2
Status.Todo;                             // 0
Status[0];                               // "Todo" — reverse mapping (μόνο σε numeric)

enum Role { Admin = "admin", User = "user" }  // string enum: πιο ασφαλές & αναγνώσιμο σε logs/DB
```

Τα προβλήματα των numeric enums: η τιμή που αποθηκεύεις στη βάση είναι ένα `0` (και αν αναδιατάξεις τα μέλη, αλλάζει σιωπηλά η σημασία των παλιών δεδομένων), και ένα σκέτο `2` γίνεται δεκτό εκεί που περιμένει `Status`. Επιπλέον, ο compiler παράγει ένα ολόκληρο object με IIFE στο bundle. Το `const enum` το αποφεύγει (κάνει inline τις τιμές) αλλά **δεν δουλεύει** με τα σύγχρονα build tools που κάνουν type stripping ανά αρχείο (Next.js, Vite, `isolatedModules`) — γι' αυτό αποφεύγεται κι αυτό.

Τα **literal unions** το αντικαθιστούν: σκέτα strings στη runtime, μηδενικό overhead, εύκολο JSON, καμία ανάγκη import. Όταν θες και τις **τιμές** ως object (όχι μόνο τον τύπο), το pattern είναι `as const`:

```ts
const STATUS = ["todo", "doing", "done"] as const;
type Status = (typeof STATUS)[number]; // "todo" | "doing" | "done" — παράγεται από τον πίνακα

const ROLES = { admin: "admin", user: "user" } as const;
type Role = (typeof ROLES)[keyof typeof ROLES];
```

Το `as const` «παγώνει» μια τιμή στον **πιο στενό** τύπο (literal, readonly), αντί να την πλατύνει σε `string`/`string[]`. Έτσι έχεις ένα source of truth και για τιμές και για τύπους.

> Πότε `enum`; Αν η ομάδα/κώδικας ήδη το χρησιμοποιεί, ή θες named numeric constants. Για νέα fullstack apps, literal unions ή `as const` objects είναι η συνήθης σύσταση.

## Discriminated unions — το πιο δυνατό pattern

Αυτό ξεχωρίζει όσους «γράφουν TypeScript» από όσους τον αξιοποιούν. Ένα κοινό literal field (ο **discriminant**) κάνει τα invalid states αδύνατα:

```ts
type ApiResult<T> =
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };

function render(result: ApiResult<string[]>) {
  switch (result.status) {
    case "loading":
      return "Loading…";
    case "success":
      return result.data.length;     // ✅ το data υπάρχει ΜΟΝΟ εδώ
    case "error":
      return result.message;         // ✅ το message υπάρχει ΜΟΝΟ εδώ
  }
}
```

Σύγκρινε με το «αφελές» `{ loading: boolean; data?: T; error?: string }` — εκεί τίποτα δεν εμποδίζει `loading: true` μαζί με `error`. Με το discriminated union, ο compiler **αποδεικνύει** ότι χειρίστηκες κάθε περίπτωση.

## Exhaustiveness checking με `never`

Το `never` είναι ο τύπος του «αδύνατου» — τιμή που δεν μπορεί να υπάρξει. Η πρακτική του χρήση: αν προσθέσεις νέο μέλος στο union και ξεχάσεις ένα case, ο compiler το πιάνει:

```ts
function render(result: ApiResult<string[]>) {
  switch (result.status) {
    case "loading": return "…";
    case "success": return "ok";
    case "error":   return "err";
    default: {
      const unreachable: never = result; // ❌ compile error αν έμεινε case εκτός
      return unreachable;
    }
  }
}
```

## Custom type guards (`x is Foo`)

Όταν το narrowing δεν προκύπτει αυτόματα, γράφεις δική σου **type predicate** function που επιστρέφει `param is Type`:

```ts
interface Cat { meow: () => void }
interface Dog { bark: () => void }

function isCat(animal: Cat | Dog): animal is Cat {
  return "meow" in animal;
}

function speak(animal: Cat | Dog) {
  if (isCat(animal)) {
    animal.meow();   // ✅ ο compiler ξέρει: Cat
  } else {
    animal.bark();   // ✅ εδώ: Dog
  }
}
```

Το `animal is Cat` λέει στον compiler: «αν αυτή η function γυρίσει `true`, ο τύπος είναι `Cat`». Χρήσιμο για validation, για unknown data, και για να καθαρίσεις σύνθετο narrowing σε επαναχρησιμοποιήσιμη function.

## Πώς απαντάς στη συνέντευξη

> «How do you model state safely in TypeScript?»

> Literal unions over enums — they're plain strings at runtime, zero overhead, easy JSON, no import needed; when I need the values as an object too I use `as const` and derive the type from it, so there's one source of truth. For state with variants I reach for discriminated unions: a shared literal field like `status` means the compiler narrows each branch and makes invalid combinations — loading and error at once — impossible to even write. I add an exhaustiveness check by assigning the leftover to `never` in the default case, so adding a new variant turns every unhandled switch into a compile error. And when narrowing isn't automatic, I write a custom type guard — a function returning `x is Foo` — to teach the compiler the shape.
