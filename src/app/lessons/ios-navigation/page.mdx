# Navigation

Μια πραγματική app έχει πολλές οθόνες: λίστα → λεπτομέρεια, tabs, modals, ρυθμίσεις. Το SwiftUI χειρίζεται την πλοήγηση **declaratively** — δεν λες «σπρώξε αυτή την οθόνη», αλλά περιγράφεις **ποια οθόνη αντιστοιχεί σε ποια κατάσταση/τιμή**. Από το iOS 16 το σύγχρονο εργαλείο είναι το **`NavigationStack`** με **value-based navigation**, που κάνει και το **programmatic** navigation (π.χ. deep links, «πήγαινε στο checkout») καθαρό.

## Τι πρέπει να μπορείς στο τέλος

- να στήνεις stack navigation με `NavigationStack` + `NavigationLink`,
- να κάνεis **value-based** navigation με `navigationDestination`,
- να ελέγχεις προγραμματιστικά το back stack μέσω **path binding**,
- να φτιάχνεις tabs με `TabView`,
- να παρουσιάζεις modals με `.sheet` / `.fullScreenCover`,
- να χειρίζεσαι deep links.

## `NavigationStack` + `NavigationLink`

Το πιο απλό push navigation: τυλίγεις το περιεχόμενο σε `NavigationStack` και βάζεις `NavigationLink`:

```swift
NavigationStack {
    List {
        NavigationLink("Ρυθμίσεις") {
            SettingsView()   // η οθόνη-προορισμός
        }
        NavigationLink("Προφίλ") {
            ProfileView()
        }
    }
    .navigationTitle("Αρχική")
}
```

Πατάς → push η νέα οθόνη με native back button & swipe-back **δωρεάν**. Ο τίτλος μπαίνει με `.navigationTitle(...)`.

## Value-based navigation — `navigationDestination`

Το inline `NavigationLink { DestinationView() }` είναι εντάξει για λίγες σταθερές οθόνες. Για **δεδομένα-οδηγούμενη** πλοήγηση (λίστα προϊόντων → σελίδα προϊόντος) το idiomatic pattern είναι να συνδέεις μια **τιμή** με έναν προορισμό:

```swift
NavigationStack {
    List(products) { product in
        NavigationLink(product.title, value: product)   // δίνεις ΤΙΜΗ, όχι view
    }
    .navigationDestination(for: Product.self) { product in
        ProductDetailView(product: product)   // η τιμή → η οθόνη
    }
}
```

- Το `NavigationLink(value:)` λέει «όταν πατηθεί, βάλε αυτή την **τιμή** στο stack».
- Το `.navigationDestination(for:)` λέει «για τιμές τύπου `Product`, δείξε αυτή την οθόνη».
- Η τιμή πρέπει να είναι `Hashable`.

> Γιατί value-based; **Αποσυνδέει το «τι» από το «πώς φαίνεται».** Ένα cell δεν χρειάζεται να ξέρει τη detail view· απλώς εκπέμπει μια τιμή. Το ίδιο pattern κάνει trivial το programmatic navigation και τα deep links — παρακάτω.

## Programmatic navigation — path binding

Μερικές φορές πρέπει να πλοηγηθείς **από κώδικα**: μετά από login πήγαινε στο home, από notification πήγαινε στο μήνυμα, ή «πίσω στη ρίζα». Δίνεις στο `NavigationStack` ένα **binding σε ένα path** (πίνακα τιμών) που εσύ ελέγχεις:

```swift
@State private var path: [Product] = []

NavigationStack(path: $path) {
    List(products) { p in
        NavigationLink(p.title, value: p)
    }
    .navigationDestination(for: Product.self) { ProductDetailView(product: $0) }
}

// Οπουδήποτε στον κώδικα:
path.append(someProduct)   // push προγραμματιστικά
path.removeLast()          // pop
path = []                  // πίσω στη ρίζα (pop to root)
```

Ο πίνακας `path` **ΕΙΝΑΙ** το back stack: κάθε στοιχείο = μία οθόνη στο stack. Το μεταλλάσσεις και το UI ακολουθεί — καθαρό declarative μοντέλο. (Για ανάμεικτους τύπους οθονών υπάρχει το `NavigationPath` που κρατά heterogeneous τιμές.)

## Tabs — `TabView`

Για top-level ενότητες (Home / Search / Profile) που ζουν παράλληλα:

```swift
TabView {
    HomeView()
        .tabItem { Label("Αρχική", systemImage: "house") }
    SearchView()
        .tabItem { Label("Αναζήτηση", systemImage: "magnifyingglass") }
    ProfileView()
        .tabItem { Label("Προφίλ", systemImage: "person") }
}
```

> **Κάθε tab έχει το δικό του `NavigationStack`.** Έτσι κάθε tab κρατά ανεξάρτητο back stack — αλλάζεις tab, γυρνάς πίσω, και το προηγούμενο tab είναι εκεί που το άφησες. Μη βάζεις ένα `NavigationStack` γύρω από όλο το `TabView`.

## Modals — `.sheet` & `.fullScreenCover`

Οι modal παρουσιάσεις (φόρμα, φίλτρα, «νέο αντικείμενο») δεν είναι μέρος του stack — αναδύονται πάνω από την οθόνη. Ελέγχονται από **boolean state** ή από **optional item**:

```swift
@State private var showingFilters = false

Button("Φίλτρα") { showingFilters = true }
    .sheet(isPresented: $showingFilters) {
        FiltersView()
    }
```

Item-based (όταν το modal εξαρτάται από συγκεκριμένο δεδομένο):

```swift
@State private var editing: Product?

.sheet(item: $editing) { product in
    EditProductView(product: product)   // ανοίγει όταν editing != nil
}
```

Μέσα στο modal, το κλείσιμο γίνεται με `@Environment(\.dismiss)`:

```swift
@Environment(\.dismiss) private var dismiss
Button("Άκυρο") { dismiss() }
```

Το `.fullScreenCover` είναι το ίδιο αλλά καλύπτει όλη την οθόνη (π.χ. onboarding, camera).

## Deep links

Ένα deep link (`myapp://product/42`, universal link, ή notification tap) πρέπει να οδηγήσει σε συγκεκριμένη οθόνη. Με το value-based μοντέλο είναι απλό: **μετάφρασε το URL σε τιμές και βάλ' τις στο `path`**:

```swift
.onOpenURL { url in
    if let id = parseProductId(url),
       let product = store.product(id: id) {
        path = [product]   // πηγαίνει κατευθείαν στη detail οθόνη
    }
}
```

Επειδή το `path` είναι απλός πίνακας κατάστασης, ένα deep link είναι απλώς «θέσε το σωστό path» — καμία ειδική μηχανική.

## Πώς απαντάς στη συνέντευξη

> «How do you handle navigation in modern SwiftUI?»

> I use `NavigationStack` for push-style navigation. For anything data-driven I prefer value-based navigation: a `NavigationLink(value:)` pushes a `Hashable` value, and a `navigationDestination(for:)` centrally maps that value type to a destination view. This decouples a cell from the screen it opens — the cell just emits a value. It also makes programmatic navigation clean, because a `NavigationStack(path:)` binding gives me an array that *is* the back stack: I `append` to push, `removeLast` to pop, and set it to empty to pop to root. Deep links become trivial — I translate the URL into values and set the path. For top-level sections I use a `TabView` where each tab has its own `NavigationStack` so each keeps an independent back stack. And modals aren't part of the stack — I present them with `.sheet` driven by boolean or optional-item state, and dismiss with the `dismiss` environment action.
