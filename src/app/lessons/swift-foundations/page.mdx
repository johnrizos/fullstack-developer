# Swift Foundations

Το **Swift** είναι η γλώσσα της Apple για iOS, iPadOS, macOS, watchOS και tvOS — από το 2014 αντικατέστησε το Objective-C ως η προτεινόμενη γλώσσα, και το **SwiftUI** είναι Swift-only. Είναι στατικά τυπωμένη (statically typed), compiled, και σχεδιάστηκε με **safety** ως πρώτη προτεραιότητα: όπως και το Kotlin, βάζει το **null safety** μέσα στο type system μέσω των **optionals**. Αν ξέρεις TypeScript ή Kotlin, πολλά θα σου φανούν οικεία — αλλά υπάρχουν δύο ιδέες που ορίζουν το Swift: τα **optionals** και η διάκριση **value types vs reference types**.

Αυτό το μάθημα είναι **μόνο η γλώσσα** — όχι ακόμα SwiftUI. Χτίζουμε το vocabulary που θα χρησιμοποιείς σε κάθε επόμενο μάθημα.

## Τι πρέπει να μπορείς στο τέλος

- να διαλέγεις `let` vs `var` και να εξηγείς γιατί προτιμάς immutability,
- να χειρίζεσαι optionals με ασφάλεια (`if let`, `guard let`, `??`, `?.`) και να ξέρεις γιατί το force-unwrap `!` είναι code smell,
- να ξεχωρίζεις **struct (value type)** από **class (reference type)** και να ξέρεις ποιο διαλέγεις,
- να γράφεις `enum` με **associated values** και να το χειρίζεσαι με `switch`,
- να ορίζεις `protocol` και να καταλαβαίνεις το protocol-oriented μοντέλο,
- να χρησιμοποιείς closures και τα βασικά functional APIs (`map`/`filter`).

## `let` vs `var` — immutability by default

```swift
let name = "Giannis"   // σταθερά — δεν μπορεί να ξανα-ανατεθεί
var count = 0          // μεταβλητή — μπορεί να αλλάξει
count += 1             // OK
// name = "Άλλο"       // compile error
```

Ο τύπος **συνάγεται** (type inference): το `let name = "Giannis"` είναι αυτόματα `String`. Μπορείς να τον δηλώσεις ρητά: `let name: String = "Giannis"`.

> Κανόνας: **ξεκίνα πάντα με `let`.** Άλλαξε σε `var` μόνο όταν πραγματικά χρειάζεσαι reassignment. Ο compiler μάλιστα σε προειδοποιεί αν δηλώσεις `var` που δεν άλλαξε ποτέ. Ο immutable κώδικας είναι κρίσιμος στο SwiftUI (θα το δεις στο state μάθημα).

## Optionals — το χαρακτηριστικό που ορίζει το Swift

Στη Swift, μια κανονική μεταβλητή **ΔΕΝ** μπορεί να είναι `nil` (το ισοδύναμο του null). Αν θέλεις να επιτρέψεις απουσία τιμής, δηλώνεις **optional** με `?`:

```swift
var a: String = "hello"
// a = nil               // compile error — ο String ΔΕΝ δέχεται nil

var b: String? = "hello" // το ? σημαίνει "String ή nil"
b = nil                  // OK
```

Ο compiler σε **αναγκάζει** να ξετυλίξεις (unwrap) το optional πριν το χρησιμοποιήσεις. Οι τρόποι:

```swift
// 1. if let — μπες στο block μόνο αν έχει τιμή
if let value = b {
    print(value.count)   // εδώ το value είναι σκέτο String (non-optional)
}

// 2. guard let — βγες νωρίς αν είναι nil (early return, "happy path" μένει flat)
func greet(_ b: String?) {
    guard let value = b else { return }
    print("Γεια \(value)")   // από εδώ και κάτω το value είναι non-optional
}

// 3. Nil-coalescing ?? — δώσε default
let value = b ?? "άγνωστο"

// 4. Optional chaining ?. — αν nil, όλη η έκφραση γίνεται nil
let len: Int? = b?.count

// 5. Force unwrap ! — "εγγυώμαι ότι δεν είναι nil" — CRASH αν κάνεις λάθος
let len2 = b!.count
```

| Σύμβολο | Τι κάνει |
|---|---|
| `?` (στον τύπο) | Δηλώνει optional: `String?` |
| `if let` / `guard let` | Ξετυλίγει με ασφάλεια σε binding |
| `??` | Nil-coalescing — default όταν αριστερά είναι nil |
| `?.` | Optional chaining — αν nil, η έκφραση γίνεται nil |
| `!` | Force unwrap — «σκάσε (crash) αν είναι nil» |

> Το force-unwrap `!` είναι **code smell**: λες στον compiler «εμπιστέψου με» και ξαναφέρνεις τα crashes. Χρησιμοποίησέ το μόνο όταν αποδεδειγμένα δεν γίνεται nil (π.χ. `@IBOutlet`, hardcoded resources)· αλλιώς προτίμησε `if let`/`guard let`/`??`.

Το `guard let` είναι το πιο idiomatic pattern: κάνει **early return** για τις κακές περιπτώσεις και αφήνει το «καλό» μονοπάτι flat, χωρίς nesting.

## Value types vs reference types — `struct` vs `class`

Αυτή είναι η **πιο σημαντική** διάκριση του Swift και συχνή interview ερώτηση.

```swift
struct PointS { var x: Int }   // VALUE type — αντιγράφεται
class  PointC { var x: Int; init(x: Int) { self.x = x } }  // REFERENCE type — μοιράζεται

var a = PointS(x: 1)
var b = a            // ΑΝΤΙΓΡΑΦΟ
b.x = 99
print(a.x)           // 1  — το a δεν επηρεάστηκε

var c = PointC(x: 1)
var d = c            // ΙΔΙΟ αντικείμενο (κοινό reference)
d.x = 99
print(c.x)           // 99 — άλλαξε και το c
```

- **`struct` = value type**: όταν το αναθέτεις ή το περνάς σε function, **αντιγράφεται**. Δύο μεταβλητές δεν μοιράζονται κατάσταση. Ζει (συνήθως) στο stack.
- **`class` = reference type**: αναθέτεις/περνάς το **reference**· δύο μεταβλητές δείχνουν στο ίδιο αντικείμενο. Ζει στο heap, έχει identity (`===`), υποστηρίζει inheritance.

> Στη Swift ο κανόνας είναι: **ξεκίνα με `struct`.** Τα περισσότερα models, τα SwiftUI views, ακόμα και `String`/`Array`/`Dictionary` είναι structs. Πήγαινε σε `class` μόνο όταν χρειάζεσαι **shared mutable state**, identity, inheritance, ή interop με UIKit/Objective-C. Το value semantics κάνει τον κώδικα προβλέψιμο — κανένα spooky action σε απόσταση.

Τα structs έχουν αυτόματα **memberwise initializer** (`PointS(x: 1)`) — δεν γράφεις `init` με το χέρι.

## Enums με associated values

Τα `enum` της Swift είναι πολύ πιο δυνατά από άλλες γλώσσες: κάθε case μπορεί να κουβαλά **δικά του δεδομένα** (associated values) — ακριβώς σαν το `sealed class` του Kotlin:

```swift
enum UiState {
    case loading
    case success([Product])   // κουβαλά μια λίστα
    case error(String)        // κουβαλά ένα μήνυμα
}

func render(_ state: UiState) -> String {
    switch state {
    case .loading:
        return "Φόρτωση…"
    case .success(let items):
        return "\(items.count) προϊόντα"
    case .error(let message):
        return message
    // χωρίς default! Ο compiler ξέρει ότι κάλυψες όλα τα cases
    }
}
```

> Το `switch` στη Swift είναι **exhaustive**: πρέπει να καλύψεις κάθε case (αλλιώς compile error). Αυτό το `enum` + `switch` pattern θα το δεις **παντού** στο iOS UI state (loading/success/error). Αν προσθέσεις νέο case, ο compiler σε αναγκάζει να ενημερώσεις κάθε `switch`.

## Structs, computed properties & methods

```swift
struct Product {
    let id: String
    var title: String
    var price: Double

    // computed property — υπολογίζεται κάθε φορά
    var displayPrice: String { "€\(price)" }

    // method
    func discounted(by pct: Double) -> Product {
        var copy = self
        copy.price = price * (1 - pct)
        return copy      // immutable-style update: νέο αντίγραφο
    }
}

let p = Product(id: "1", title: "Καφές", price: 3.5)
print(p.displayPrice)          // €3.5
let cheaper = p.discounted(by: 0.2)
```

Επειδή το `Product` είναι struct (value type), το `discounted` επιστρέφει **νέο αντίγραφο** αντί να μεταλλάσσει — ταιριάζει τέλεια με το state model του SwiftUI.

## Protocols — το «interface» της Swift

Ένα `protocol` ορίζει ένα **contract**: τι properties/methods πρέπει να έχει ένας τύπος. Structs, classes και enums μπορούν να το **conform**:

```swift
protocol Identifiable {
    var id: String { get }
}

struct User: Identifiable {
    let id: String
    let name: String
}
```

Η Swift είναι **protocol-oriented**: αντί για βαθιές ιεραρχίες κληρονομικότητας, συνθέτεις συμπεριφορά μέσω protocols (και protocol extensions με default implementations). Πολλά built-in protocols θα τα δεις συνέχεια: `Codable` (JSON), `Identifiable` (SwiftUI lists), `Equatable`, `Hashable`.

## Closures & functional API

Τα **closures** είναι anonymous functions (σαν τα JS arrow functions / Kotlin lambdas):

```swift
let nums = [3, 1, 2]

let doubled = nums.map { $0 * 2 }          // [6, 2, 4]
let evens   = nums.filter { $0 % 2 == 0 }  // [2]
let sum     = nums.reduce(0, +)            // 6
let sorted  = nums.sorted()                // [1, 2, 3]
```

Το `$0` είναι το implicit όνομα του πρώτου parameter. Το closure που είναι το **τελευταίο** argument βγαίνει έξω από τις παρενθέσεις (trailing closure): `nums.map { $0 * 2 }`.

## Πώς απαντάς στη συνέντευξη

> «What are optionals in Swift, and how do value and reference types differ?»

> An optional is Swift's way of encoding "a value or nothing" directly in the type system. A `String` can never be nil; only a `String?` can, and the compiler forces me to unwrap it before use. I reach for `if let` or `guard let` to safely bind it, `??` for a default, and optional chaining `?.` to short-circuit. Force-unwrapping with `!` crashes on nil, so I treat it as a code smell. The other defining idea is value vs reference types: a `struct` is a value type — it's copied on assignment, so two variables never share state — while a `class` is a reference type, shared by reference with identity and inheritance. Swift's default is `struct`, and even `String`, `Array`, and SwiftUI views are structs. I only reach for a `class` when I genuinely need shared mutable state, identity, inheritance, or UIKit interop. Value semantics make the code predictable, which matters a lot for SwiftUI's state model.
