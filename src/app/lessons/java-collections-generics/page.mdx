# Collections, Generics & Streams

Ο πραγματικός κώδικας δουλεύει συνέχεια με **συλλογές δεδομένων**: λίστες προϊόντων, χάρτες από id σε χρήστη, σύνολα από tags. Η Java έχει ένα πλούσιο **Collections Framework**, τα **generics** για type safety, και το **Stream API** για δηλωτική επεξεργασία (filter/map/reduce χωρίς loops). Αυτά τα τρία είναι από τα πιο πρακτικά — και πιο συχνά στα interviews — εργαλεία της γλώσσας.

## Τι πρέπει να μπορείς στο τέλος

- να διαλέγεις σωστά ανάμεσα σε `List`, `Set`, `Map` (και τις υλοποιήσεις τους),
- να καταλαβαίνεις **generics** & type safety (`List<String>`, bounded types),
- να γράφεις **lambdas** & method references,
- να επεξεργάζεσαι δεδομένα με το **Stream API** (`filter`/`map`/`collect`),
- να χειρίζεσαι απόντα δεδομένα με **`Optional<T>`** αντί για null.

## Το Collections Framework

Τρεις βασικές διεπαφές, με πολλές υλοποιήσεις:

| Interface | Τι είναι | Κύρια υλοποίηση | Πότε |
|---|---|---|---|
| **`List`** | διατεταγμένη, επιτρέπει διπλά | `ArrayList` | σειρά μετράει, index access |
| **`Set`** | μοναδικά στοιχεία, χωρίς διπλά | `HashSet` | deduplication, membership |
| **`Map`** | ζεύγη key→value | `HashMap` | lookup με κλειδί |

```java
List<String> names = new ArrayList<>();
names.add("Άννα");
names.add("Άννα");           // επιτρέπεται (διπλό)
names.get(0);                 // index access

Set<String> tags = new HashSet<>();
tags.add("java");
tags.add("java");             // αγνοείται — ήδη υπάρχει
tags.contains("java");        // O(1) lookup

Map<String, Integer> ages = new HashMap<>();
ages.put("Άννα", 30);
ages.get("Άννα");             // 30
ages.getOrDefault("Χ", 0);    // 0 αν λείπει
```

> **Programming to the interface:** δηλώνεις `List<String> x = new ArrayList<>()` — ο τύπος της μεταβλητής είναι το **interface** (`List`), όχι η υλοποίηση. Έτσι μπορείς να αλλάξεις σε `LinkedList` χωρίς να πειράξεις τον υπόλοιπο κώδικα. Interview note: `ArrayList` = γρήγορο index access· `HashMap`/`HashSet` = O(1) lookup χάρη στο hashing (γι' αυτό τα keys χρειάζονται σωστό `equals`/`hashCode` — εδώ βοηθούν τα records).

## Generics — type safety

Τα **generics** επιτρέπουν σε μια κλάση/μέθοδο να δουλεύει με **οποιονδήποτε τύπο**, διατηρώντας **compile-time type safety**. Το `<String>` λέει «αυτή η λίστα κρατά μόνο Strings»:

```java
List<String> names = new ArrayList<>();
names.add("Άννα");
// names.add(42);        // compile error — μόνο String
String first = names.get(0);   // χωρίς cast — ο compiler ξέρει τον τύπο
```

Πριν τα generics, οι λίστες κρατούσαν `Object` και χρειαζόσουν χειροκίνητα casts (με κίνδυνο `ClassCastException` στο runtime). Τα generics μεταφέρουν αυτόν τον έλεγχο στο **compile time**.

Δικά σου generic types & **bounded types**:

```java
// Generic method — δουλεύει για κάθε T
public <T> T firstOrNull(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}

// Bounded: το T πρέπει να είναι Number (ή subclass)
public <T extends Number> double sum(List<T> nums) {
    double total = 0;
    for (T n : nums) total += n.doubleValue();
    return total;
}
```

> **Type erasure** (interview classic): τα generics υπάρχουν μόνο σε **compile time** — το JVM τα «σβήνει» στο runtime (ένα `List<String>` γίνεται απλώς `List`). Γι' αυτό δεν μπορείς π.χ. `new T()` ή `if (x instanceof List<String>)`. Ο σκοπός τους είναι compile-time safety, όχι runtime πληροφορία.

## Lambdas & functional interfaces

Μια **lambda** είναι σύντομη σύνταξη για μια συνάρτηση — υλοποιεί ένα **functional interface** (interface με μία abstract method):

```java
// Παλιά (anonymous class)
Runnable r = new Runnable() {
    public void run() { System.out.println("hi"); }
};

// Lambda
Runnable r = () -> System.out.println("hi");

// Με παραμέτρους
Comparator<String> byLength = (a, b) -> a.length() - b.length();

// Method reference — ακόμα πιο σύντομο
names.forEach(System.out::println);
```

Οι lambdas είναι το θεμέλιο του Stream API. Συχνά functional interfaces: `Function<T,R>`, `Predicate<T>` (επιστρέφει boolean), `Consumer<T>`, `Supplier<T>`.

## Stream API — δηλωτική επεξεργασία

Ένα **Stream** επιτρέπει να επεξεργάζεσαι collections **δηλωτικά** — αλυσίδα από operations αντί για loops (ανάλογο των JS array methods / Kotlin sequences):

```java
List<Product> products = ...;

List<String> cheapTitles = products.stream()
    .filter(p -> p.price() < 10)              // κράτα τα φθηνά
    .map(Product::title)                       // πάρε μόνο τον τίτλο
    .sorted()                                  // ταξινόμησε
    .toList();                                 // μάζεψε σε List

double total = products.stream()
    .mapToDouble(Product::price)
    .sum();

Map<String, List<Product>> byCategory = products.stream()
    .collect(Collectors.groupingBy(Product::category));
```

- **Intermediate** operations (`filter`, `map`, `sorted`) είναι **lazy** — δεν τρέχουν μέχρι να έρθει terminal.
- **Terminal** operations (`toList`, `sum`, `collect`, `forEach`) ενεργοποιούν την αλυσίδα και παράγουν αποτέλεσμα.

> Οφέλη: πιο **αναγνώσιμος** κώδικας (λες *τι* θέλεις, όχι *πώς*), λιγότερα bugs από manual loops, και εύκολη παραλληλοποίηση (`.parallelStream()`). Τα streams **δεν** μεταλλάσσουν την πηγή — παράγουν νέο αποτέλεσμα. Interview note: intermediate = lazy, terminal = eager.

## `Optional<T>` — ρητή απουσία

Το **`Optional<T>`** είναι ένα container που μπορεί να περιέχει τιμή **ή όχι** — ρητός τρόπος να εκφράσεις «μπορεί να λείπει», αντί να επιστρέφεις `null`:

```java
public Optional<Product> findById(String id) {
    // ...
    return Optional.ofNullable(product);   // empty αν null
}

// Χρήση — ο caller ΑΝΑΓΚΑΖΕΤΑΙ να σκεφτεί το «λείπει»
String title = findById("1")
    .map(Product::title)
    .orElse("Άγνωστο");        // default αν empty

findById("1").ifPresent(p -> System.out.println(p.title()));
```

> Το `Optional` κάνει το «μπορεί να μην υπάρχει» **ορατό στην υπογραφή** — ο caller δεν μπορεί να το αγνοήσει όπως ένα σιωπηλό null. Είναι η πλησιέστερη Java απάντηση στο null safety της Kotlin. Best practice: χρησιμοποίησέ το ως **return type** για «μπορεί να λείπει»· **μην** το βάζεις σε fields/parameters ούτε να καλείς `.get()` χωρίς έλεγχο (ισοδυναμεί με NPE).

## Πώς απαντάς στη συνέντευξη

> «How do you work with collections and process data in Java?»

> The Collections Framework gives me three core interfaces: `List` for ordered data that allows duplicates, usually `ArrayList`; `Set` for unique elements with fast membership, usually `HashSet`; and `Map` for key-to-value lookup, usually `HashMap`. I program to the interface — declare a `List` but instantiate an `ArrayList` — so I can swap implementations freely. Generics like `List<String>` give me compile-time type safety: the compiler rejects a wrong type and I never need casts, which moves errors from runtime `ClassCastException` to compile time. One subtlety is type erasure — generics exist only at compile time and are erased at runtime. For processing I use the Stream API: I chain `filter`, `map`, `sorted`, and finish with a terminal like `toList` or `collect`. Intermediate operations are lazy and only run when the terminal fires, which makes the code declarative and easy to parallelize, and streams don't mutate the source. For values that might be absent I return `Optional<T>` instead of null, so the absence is visible in the signature and the caller has to handle it with `map` and `orElse` — it's Java's closest answer to Kotlin's null safety.
