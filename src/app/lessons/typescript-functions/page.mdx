# Typing Functions & Async

Οι functions είναι το σημείο όπου το TypeScript δίνει τη μεγαλύτερη αξία: το signature είναι το «συμβόλαιο» — τι μπαίνει, τι βγαίνει. Αυτό το μάθημα καλύπτει typing παραμέτρων (optional/default/rest), return types, function types ως values, overloads, και — κρίσιμο για fullstack — το typing του **async** κώδικα με `Promise<T>` και `Awaited<T>`.

## Παράμετροι: optional, default, rest

```ts
function createUser(
  name: string,
  age?: number,                // optional — γίνεται number | undefined
  role: string = "user",       // default — ο τύπος συμπεραίνεται (string)
  ...tags: string[]            // rest — μαζεύει τα υπόλοιπα σε array
): void {}

createUser("Ada");
createUser("Ada", 30, "admin", "vip", "beta");
```

Δύο κανόνες: τα **optional** (`?`) και τα **default** params μπαίνουν μετά τα required· ένα optional param έχει τύπο `T | undefined`, άρα ο compiler σε αναγκάζει να το χειριστείς.

### Destructured parameters — το συντακτικό που μπερδεύει

Όταν κάνεις destructuring στην παράμετρο, ο τύπος μπαίνει **στο σύνολο**, όχι σε κάθε πεδίο:

```ts
function createTask({ title, done = false }: { title: string; done?: boolean }) {}

// Με named type — έτσι το γράφεις στην πράξη:
interface CreateTaskInput { title: string; done?: boolean }
function createTask2({ title, done = false }: CreateTaskInput) {}

// Ολόκληρο object optional:
function search({ q = "", page = 1 }: { q?: string; page?: number } = {}) {}
```

Παγίδα αρχαρίων: το `{ title: string }` **μέσα** στο destructuring pattern δεν είναι τύπος — είναι μετονομασία (`title` → μεταβλητή `string`). Ο τύπος πάει πάντα μετά τα `}` με `:`.

## Return types: άσε το inference, εκτός από τα όρια

Ο compiler συμπεραίνει το return type. Καλό για τοπικές functions· για **exported / public** functions βάλε explicit return type — λειτουργεί ως συμβόλαιο και πιάνει λάθη μέσα στη function:

```ts
function add(a: number, b: number): number {
  return a + b;
}

function logMessage(msg: string): void {} // δεν επιστρέφει τίποτα χρήσιμο
function fail(): never { throw new Error(); } // δεν επιστρέφει ΠΟΤΕ (throw/infinite)
```

`void` = «δεν επιστρέφει χρήσιμη τιμή». `never` = «δεν επιστρέφει καθόλου» (throw ή ατέρμονο).

## Function types ως values

Μια function είναι τιμή — έχει και αυτή τύπο. Χρήσιμο για callbacks/handlers:

```ts
type Transformer = (input: string) => string;

const upper: Transformer = (s) => s.toUpperCase(); // το s είναι string από το type
function apply(fn: (n: number) => number, x: number) {
  return fn(x);
}
```

Πρόσεξε το `(s) => ...`: **δεν** χρειάστηκε annotation. Αυτό λέγεται **contextual typing** — όταν ο compiler ξέρει τι τύπο περιμένει σε αυτή τη θέση, δίνει τύπους στις παραμέτρους μόνος του. Είναι ο λόγος που δεν τυπώνεις ποτέ τα callbacks των array methods:

```ts
const nums = [1, 2, 3];
nums.map((n) => n * 2);          // το n είναι number αυτόματα — μην γράψεις (n: number)
tasks.filter((t) => t.done);     // το t είναι Task

// Χάνεται όταν βγάλεις τη function από το context:
const double = (n) => n * 2;     // ❌ Parameter 'n' implicitly has an 'any' type
const double2 = (n: number) => n * 2;                    // ✅ annotation
const double3: (n: number) => number = (n) => n * 2;     // ✅ ή τύπος στη μεταβλητή
```

### Τυπώνοντας το `this`

Σε μια κανονική `function` το `this` εξαρτάται από το πώς καλείται. Αν το χρειάζεσαι typed, το δηλώνεις ως **πρώτη ψευδο-παράμετρο** (εξαφανίζεται στο compile — δεν είναι πραγματικό argument):

```ts
function handleClick(this: HTMLButtonElement, event: MouseEvent) {
  this.disabled = true;   // ✅ typed
}
button.addEventListener("click", handleClick);
```

Στις arrow functions δεν υπάρχει δικό τους `this` (κληρονομείται λεξικά), γι' αυτό και δεν δέχονται `this` παράμετρο — και γι' αυτό είναι η ασφαλής επιλογή για callbacks.

## Overloads — διαφορετικά signatures για ίδια function

Όταν μια function συμπεριφέρεται διαφορετικά ανά είσοδο, δηλώνεις πολλαπλά **overload signatures** πάνω από μία implementation:

```ts
function parse(value: string): string[];
function parse(value: number): number;
function parse(value: string | number): string[] | number {
  return typeof value === "string" ? value.split(",") : value * 2;
}

const a = parse("a,b,c"); // τύπος: string[]
const b = parse(10);      // τύπος: number
```

Συχνά ένα union/generic είναι απλούστερο από overloads — κράτα τα overloads για όταν η σχέση input→output δεν εκφράζεται αλλιώς.

## Typing async κώδικα

Μια `async` function επιστρέφει **πάντα** `Promise<T>`. Το `await` «ξετυλίγει» το `T`:

```ts
async function getUser(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  return res.json() as Promise<User>;
}

const user = await getUser("1"); // τύπος: User (το Promise ξετυλίχτηκε)
```

Το `Awaited<T>` παίρνει τον «ξετυλιγμένο» τύπο ενός Promise — χρήσιμο σε generics και utility types:

```ts
type User = Awaited<ReturnType<typeof getUser>>; // User (όχι Promise<User>)
```

> Συχνό λάθος: να ξεχνάς ότι το return type μιας `async` function είναι `Promise<T>`, όχι `T`. Αν γράψεις `: User` σε async function, ο compiler διαμαρτύρεται — βάλε `: Promise<User>`.

### Η μεγάλη τρύπα: το `res.json()` είναι `any`

Ο τύπος του `Response.json()` στα built-in lib types είναι `Promise<any>`. Δηλαδή **κάθε fetch είναι μια πόρτα από την οποία μπαίνει `any` στο codebase σου** — χωρίς κανένα error, χωρίς κανένα warning:

```ts
const res = await fetch("/api/user");
const user = await res.json();   // τύπος: any 😱
user.whatever.nonsense;          // περνά καθαρά — σκάει στη runtime
```

Το `as Promise<User>` παραπάνω κλείνει την τρύπα **μόνο για τον compiler** — δεν ελέγχει τίποτα. Η σωστή λύση είναι `unknown` + runtime validation στο σύνορο (μάθημα *Type Safety & tsconfig*). Κράτα το εδώ ως τη Νο1 πηγή «κρυφού any» σε fullstack κώδικα.

### Παράλληλα Promises

```ts
const [user, tasks] = await Promise.all([getUser("1"), getTasks()]);
// user: User, tasks: Task[] — το tuple διατηρεί τον τύπο κάθε θέσης

const results = await Promise.allSettled([getUser("1"), getTasks()]);
if (results[0].status === "fulfilled") {
  results[0].value;   // discriminated union: value μόνο εδώ, reason στο "rejected"
}
```

Το `Promise.all` κρατά τη σχέση θέση→τύπος (είναι tuple, όχι array) — γι' αυτό το destructuring βγαίνει σωστά typed. Το `Promise.allSettled` επιστρέφει discriminated union, άρα ο compiler σε αναγκάζει να ελέγξεις το `status` πριν αγγίξεις το `value`.

### Τυπώνοντας τα errors — το `catch` δίνει `unknown`

Με `strict` (συγκεκριμένα `useUnknownInCatchVariables`), η μεταβλητή του `catch` είναι **`unknown`** — γιατί στη JavaScript μπορείς να κάνεις `throw` οτιδήποτε, όχι μόνο `Error`:

```ts
try {
  await getUser("1");
} catch (err) {
  err.message;                       // ❌ το unknown δεν επιτρέπει πρόσβαση
  if (err instanceof Error) {
    console.error(err.message);      // ✅ narrowed
  } else {
    console.error("Unknown error:", err);
  }
}
```

Εναλλακτική για functions που μπορεί να αποτύχουν «κανονικά» (validation, εξωτερικά APIs): αντί για `throw`, επίστρεψε **result type** — discriminated union που κάνει το σφάλμα μέρος του συμβολαίου:

```ts
type Result<T, E = string> =
  | { ok: true; value: T }
  | { ok: false; error: E };

async function getUser(id: string): Promise<Result<User>> {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) return { ok: false, error: `HTTP ${res.status}` };
  return { ok: true, value: (await res.json()) as User };
}

const result = await getUser("1");
if (result.ok) result.value.name;    // ✅ ο compiler σε υποχρεώνει να ελέγξεις
```

> Μια `Promise<T>` δεν κουβαλά **καμία** πληροφορία για το τι μπορεί να πεταχτεί — τα σφάλματα είναι αόρατα στο type system. Το result type είναι ο τρόπος να τα κάνεις ορατά.

## Πώς απαντάς στη συνέντευξη

> «How do you type functions, especially async ones?»

> The signature is the contract: I type the parameters and, for exported functions, the return type too — it documents intent and catches mistakes inside the body. Optional and default params come after required ones, and an optional param is `T | undefined`, so the compiler forces me to handle the missing case. `void` means no useful return; `never` means it never returns — it always throws or loops. For async, the key thing is that an `async` function always returns `Promise<T>`, so I annotate it `Promise<User>`, not `User`; `await` unwraps it, and `Awaited<T>` gives me the unwrapped type when I need it in a generic. I reach for overloads only when the input-to-output relationship can't be expressed with a union or generic.
